# Design Review — Что сканируется и что пропускается

## Как работает сканирование

1. **Сбор узлов** (`findAllWithCriteria`) — мгновенный, через нативный C++ движок Фигмы.
   Включены только типы из `scan-config.ts` → `SCAN_NODE_TYPES`.
   Флаг `figma.skipInvisibleInstanceChildren = true` — Фигма на уровне движка
   не возвращает детей скрытых инстансов.

2. **Синхронный pre-check** (`shouldScanNode`) — без `await`, без обращений к bridge.
   Проверяет только свойства самого узла. Отсекает мусор ДО создания Promise.

3. **Async валидация** (`validateNode`) — вызывается только для отфильтрованных узлов.
   Здесь происходят проверки переменных, стилей, компонентов.

---

## Что СКАНИРУЕТСЯ

### Компоненты (вкладка Components)
- `INSTANCE` — проверяется, совпадает ли главный компонент с эталоном (snapshot).
- `FRAME`, `COMPONENT`, `COMPONENT_SET` — то же самое.

### Переменные / цвета (вкладка Variables)
- Любой узел с заливками (`fills`) — проверяются на наличие токенов (Variables).
  Ошибка: заливка задана через Hex вместо переменной.
  Предупреждение: используется примитив вместо семантического токена.
- Любой узел с обводками (`strokes`) — аналогично.
- `TEXT` внутри компонента — проверяется токен цвета текста + текстовый стиль.
  Ошибка: стиль текста не найден в библиотеке (удалён).
  Предупреждение: переменная не из белого списка (`ds_variables.ts`).

### Градиенты (вкладка Gradients)
- Любой узел с заливкой типа `GRADIENT_*`.
  Ошибка: хардкодный градиент без токенов и стиля.
  Инфо: используется целевой стиль/токен (bonus, gamification).

### Эффекты (тени)
- Любой узел с `effects` — проверяется наличие токенов на тени.

## Что ПРОПУСКАЕТСЯ (и почему)

| Ситуация | Причина |
|---|---|
| Узел с `visible = false` | Скрытый слой, дизайнер его не видит — нет смысла проверять |
| Дети скрытого инстанса | `figma.skipInvisibleInstanceChildren = true` — Фигма их не возвращает |
| `INSTANCE` с `mainComponent.remote` | Это библиотечный компонент — мы не контролируем его внутренности |
| `VECTOR` / `BOOLEAN_OPERATION` (не иконка) | Векторные фигуры и иллюстрации — проверяются, но их дети (точки) не нужны |
| Узлы с именем "mask" или "union" | Технические графические элементы (и их содержимое) игнорируются |
| FigJam-узлы (`STICKY`, `CONNECTOR` и др.) | Не относятся к дизайну интерфейсов |
| Узлы прямо на странице или в SECTION (не иконки) | Отдельные элементы вне фреймов — декорации, артборды, документация |
| `SECTION` сам по себе | Это контейнер-организатор, не UI элемент |
| Иконки (`VECTOR`, если в имени есть "icon") | **Не пропускаются** — иконки сканируются всегда |
| `BOOLEAN_OPERATION` внутри иконки | **Не пропускается** — иконки сканируются |

## Файлы конфигурации

| Файл | Назначение |
|---|---|
| `scan-config.ts` | Типы узлов для `findAllWithCriteria` и список FigJam-узлов |
| `ds_names.ts` | Белый список официальных компонентов DS (для сверки с эталоном) |
| `ds_variables.ts` | Белый список допустимых переменных цвета текста |

## Показания счётчиков в логах (console)

```
[Design Review] Узлы собраны за Xмс. Всего узлов: N.
[Design Review] Начинаю проверку узлов...
[Design Review] Сканирование завершено за Xмс. Найдено ошибок: N
```

Количество "Всего узлов" < реального числа узлов в документе — это норма.
Фигма скрывает детей невидимых инстансов благодаря `skipInvisibleInstanceChildren`.
